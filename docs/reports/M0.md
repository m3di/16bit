## How to run it

Needs Node.js 26 and pnpm 12 (see the README for an install without corepack), plus Docker.

```sh
pnpm install
docker compose up -d db
pnpm seed               # demo workspaces: Pixel Works and Acme Studio
pnpm seed:build-hub     # this repository's issues, in the "team" workspace (needs gh)
pnpm dev                # http://localhost:5173
```

Docker only, no Node.js:

```sh
docker compose up --build                            # http://localhost:8080
docker compose run --rm app node src/seed.ts --force # demo data
```

## What was built

- **Monorepo:** `packages/core` (Zod contracts shared by both apps), `apps/api` (Fastify, Kysely, Postgres 18), `apps/web` (Vue 3, Vite, Tailwind 4), `e2e` (Playwright).
- **Core contracts:** the entities, five attribute types (text, number, boolean, date, select), `validateItemValues`, and the API request and response shapes.
- **Schema:** seven tables, with `workspace_id` leading every key. Hub isolation is enforced by foreign keys. Item numbers and revision sequence numbers come from counter columns, so they are never reused or committed out of order.
- **API:** workspace-scoped routes (D40), cursor paging, version checks with 409 and the current item, a revision row and item-count update on every write, and a dev bearer key.
- **Web:** design tokens for both themes, base components, the dashboard, and the hub view with an optimistic item panel.
- **Delivery:** CI with Postgres service containers, branch protection, a single container image in which the API serves the dashboard, and a compose stack.
- **Tests:** about 470 unit and integration tests (integration against real Postgres) and 14 end-to-end tests.

## Decisions the maintainer made during M0

- **#4:** only the five M0 attribute types for now. `null` clears a value. Booleans are indexed as 0 or 1. Dates group by UTC day. A select value whose option was deleted sorts last.
- **#5:** counter columns for item numbers and revision sequence numbers. Hub isolation is enforced in the database, which added `hubId` to `FolderAttribute`.
- **#6:** workspace-scoped routes (D40).
- **#8:** contrast fixes to the tokens, `--on-accent`, a dark palette, darker yellow and grey, 3:1 borders on inputs, and an empty hub fills no size-meter squares.
- **#26:** a `truncated` flag on hub descriptions.
- **#13:** `DEV_ANONYMOUS_AS_OWNER`, for M0 only, with a startup guard (D41).
- **Branch protection:** checks required, enforced for admins, strict mode off.

Team choices the maintainer was told about but did not formally decide: Node 26 and pnpm 12, and `core` and `api` running as TypeScript source with no build step (#1, #16). These could be recorded in `DECISIONS.md` if the maintainer agrees.

## Left out (by design or deferred)

- Everything listed under "Not in M0" in the roadmap: real auth, permissions, real time, filters, other views, MCP, comments and rich text.
- **Dashboard:** the "Waiting on you" and "Recent" columns, member counts, last active time and search. The API has no data for them, so they were left out rather than faked.
- **Item panel:** no history, because there is no revisions endpoint. "Updated by" shows the principal ID rather than a name.
- **Client mutation IDs** (ARCHITECTURE "Writes") are not built. A retry is only safe when the client supplies the item `id`.
- **Shared UI:** no shared checkbox component; booleans use a plain checkbox styled with tokens. Material Symbols is not installed yet.

## Known gaps and open questions

1. **Local toolchain:** this machine has Node 23 and a broken corepack pnpm 12 shim. Every agent worked around it, some in scratchpad copies of Node 26 and some in Docker, so CI was the only consistent check. Installing Node 26 and pnpm 12 as the README describes would fix this.
2. **End-to-end tests don't run against the container image.** The image job only checks it over HTTP.
3. **`DEV_ANONYMOUS_AS_OWNER` (D41)** has to be removed when M1 auth lands.
4. **Small review leftovers,** filed as #38:
   - The build-hub import stops the run on a `not_found` race.
   - An unchecked cast in `build-hub.ts`.
   - Duplicated test snapshot helpers.
   - `pnpm seed --force` passing through the scripts is not tested.
5. **`docs/DESIGN.md`:** in some palette colours, a filled size-meter square is under 3:1 against an empty one. Accepted for M0; revisit in M2.
6. **Demo data:** every seeded item has the same `updated_at`, so "last active" won't tell hubs apart once it's shown.

## What the team would change about the workflow

- **Check each merge step by step.** One chained command kept going after a merge failed and set labels on an issue that wasn't merged. It was caught and fixed the same day. Merges now confirm `MERGED` before anything else runs.
- **Ask for gated decisions with the first review.** The approve-on-conditions pattern ("merge once the reviewer approves and CI is green") removed a round trip on every gated PR. Asking the maintainer's questions while the first review runs, not after, saved more.
- **Expect lockfile and README conflicts.** Parallel branches kept conflicting on `pnpm-lock.yaml`, `README.md`, `ci.yml` and the scripts in `package.json`. Either merge in a deliberate order, or have authors merge `main` in before asking for review.
- **Split work by file when running in parallel.** Two backend agents and two infra agents at once worked well because their files didn't overlap.
- **Look before the end.** Exit criteria were checked by the lead against a running stack only at the end. A short check at mid-sprint would catch integration surprises earlier.
- **QA timing:** for the first features, QA was folded into #12 because no harness existed yet. In M1, QA should check each user-visible PR before it merges, as `docs/WORKFLOW.md` intends.
