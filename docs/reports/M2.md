# M2 report: dashboard and settings

Written by the lead on 2026-11-19, at the end of Sprint 2 (#123).

## Summary

The M2 exit criterion is met. `e2e/tests/m2-exit.spec.ts` signs in as an owner and, entirely in the browser, does the following:

- creates a hub from the dashboard;
- adds Text, Number, Select, Date and Checkbox attributes;
- nests folders and attaches attributes to them, with one marked required;
- sets the hub's title attribute;
- creates items with New item;
- opens one on its own page and edits it.

Each step is checked through the API. A second test invites a new person through the UI, grants them a hub as editor, and checks what an editor can and can't do. Both run in the required `End-to-end` check, with no tests marked as expected failures.

The 13 planned issues and #107, carried over from M1, are closed, along with 14 follow-ups the reviews and QA turned up, through 26 merged pull requests. Every PR was reviewed by the `reviewer` agent, and every gated change was merged only after the maintainer said yes in the conversation.

## What works

- **Workspace settings:**
  - Owners and admins manage members and roles from settings, with the role rules applied (admins can't touch owners; there's always one owner).
  - They create invite links, which are shown once, and list and revoke pending invites.
- **Hub settings, General:**
  - name, colour and title attribute (D50);
  - the hub's item total;
  - the ID prefix, read-only.
- **Hub settings, Access:** who holds a grant, add people, change roles and revoke, all following `docs/ROLES.md`. Revoked and expired agent keys are marked.
- **Hub settings, Agent keys:** create, with the secret shown once, list and revoke.
- **Hub settings, Folders:** create, rename, nest and move. A folder can't be moved under itself, and only empty folders can be deleted (D52).
- **Hub settings, Attributes:**
  - every M1 type can be created;
  - the type and a relation's target are fixed once created (D51);
  - name and options can be edited, with usage counts per option;
  - attributes can be attached to folders, reordered and marked required;
  - removing values asks first and says how many items are affected.
- **Hub settings, Danger zone:** delete an empty hub by typing its name (D52).
- **Dashboard:**
  - owners and admins create hubs, choosing a name, colour and permanent ID prefix;
  - they can grant themselves access to a "no access" hub, and the grant is logged.
- **Item page:** opens by ID and shows:
  - the title from the hub's title attribute;
  - every field, editable or read-only by hub role;
  - relations with "no access" markers, and backlinks with a hidden count;
  - delete, which checks for conflicting changes.

  New item opens it directly.
- **API:**
  - schema write routes for hubs, folders, attributes and folder attributes, each with a version check;
  - grant and invite lists;
  - per-option usage counts;
  - a narrow `delete_hub()` function.

  Removing values writes a revision per item under a per-hub lock (D55). Deleted hub and attribute IDs can't be reused.
- **Design system:**
  - settings layout, tabs, dialogs and a confirm dialog that can't be closed while busy;
  - row menu, palette picker, toggle, type picker and options editor;
  - a static table mode for rows with their own controls.

## How to run it

```sh
pnpm install
docker compose up -d db
pnpm seed           # demo workspaces; every seeded hub now has a title attribute
pnpm dev            # http://localhost:5173 — sign in as owner@example.com / 16bit-dev-password
```

Docker only: `docker compose up -d --build`, then `docker compose run --rm migrate node src/seed.ts --force`, and sign in on http://localhost:8080. The image doesn't rebuild itself when `main` changes.

## Decisions the maintainer made during M2

- **D50:** a hub names one text attribute as the item title.
- **D51:** attribute types and relation targets are fixed once created. A folder may start requiring an attribute that existing items leave empty; those items stay valid, and an edit that doesn't touch it still passes.
- **D52:** only empty folders and hubs can be deleted. Deleting a hub revokes its keys and removes its grants and attributes, and is refused while another hub's relation targets it. An admin can't delete a hub an owner holds a grant on.
- **D53:** root view editing waits for M4.
- **D54:** folder grants wait until after M2.
- **D55:** a per-hub lock keeps item writes from saving a value that is being removed.
- **`docs/ROLES.md`:**
  - owners, admins and the hub's admins can list who has access;
  - creating a cross-hub relation needs viewer access on the target;
  - footnote ¹: an admin may end an owner-role invite whose creator has been removed.
- **Migrations:**
  - 0009, schema writes: row-level security, guard triggers and `delete_hub()`, plus the `deleted_hub` record and integrity rules that also bind the owner role;
  - 0010, the invite update rule;
  - 0011, deleted attribute IDs, whose down migration refuses once any exist.
- **Core contracts:** the schema write shapes, the invite permission rules, the attribute version and hub read shapes, usage counts, and agent key states in the grant list.
- **Design:** the toggle's off track uses `--line3`; pixel glyphs instead of an icon font for now; outlined destructive buttons; a backdrop of `--bg` at 80%.

## What the team would change about the workflow

- **Planning review paid off again.** The plan went through four review rounds before any code. They turned up a missing grant list, what deleting a hub must remove, missing database privileges, and a validator conflict hidden in the wording of D51. Each became one of the maintainer's decisions instead of a mid-sprint surprise.
- **Concurrency bugs keep hiding in the database layer.** Reviewers reproduced four real races or deadlocks:
  - moving a folder against writing an item;
  - reusing a hub ID while it was being deleted;
  - redeeming an invite against revoking it;
  - an owner demoted in the middle of a request.

  The habit from M1 held: force the interleaving in a test and show it fails without the fix.
- **QA's exit test found product bugs.** Number values couldn't be set from the UI at all (#155). A row menu closed on a late scroll event, which also hit keyboard users (#157). Agents running the app on a container address found that New item hung on any plain-HTTP address other than localhost. All three are fixed.
- **Tests marked as expected failures work.** Pinning a known bug with `test.fail()` and making the fixing PR remove the pin kept `main` green and turned each fix into proof. The order matters: the pin's PR merges first.
- **QA moved into the PRs.** Each user-visible PR now carries its own end-to-end tests, and the reviewer checks they verify outcomes through the API. That was the M1 lesson, and it held.
- **Docker hung once and the shared compose stack stopped once.** No agent caused the stop. Agents now use their own containers by name and never run `docker compose` against the shared project.
- **The `#NNN` colour trap.** The web app's no-raw-colours test reads `#151` or `#157` in source comments as hex colours. Agents now write "issue 157" in web source.
