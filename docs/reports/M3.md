## What works

- **Live sync.**
  - One WebSocket per tab at `GET /v1/workspaces/:id/feed`, with subscriptions per hub (D57). Credentials, D49 and the Origin are checked before the upgrade, and a hidden hub gets the same `not_found` as a missing one.
  - Changes are read under the subscriber's own row-level security and carry the item as it is now, one per item (D58). Each message carries a high-water `seq` and the hubs it brings up to date. Past 1,000 missed changes the server sends `resync`.
  - The socket closes at once with 4401 on sign-out, member removal, key revocation, password reset or hub deletion.
  - Limits: 10 sockets per session or key, 20 subscriptions per socket, 4 KiB client messages, 256 KiB server messages that wait for the socket to drain, and a 4 MiB output buffer.
  - `GET /changes` returns the same changes over HTTP for agents and catch-up.
- **Idempotent writes (D59).** A `clientMutationId` makes an item write safe to retry. Reusing one for a different write is 422 `mutation_id_reused`.
- **The client store (D60).** A normalised store with tombstones and a pending layer, so the UI updates before the server answers and rolls back on failure. An item edited by someone else while you type keeps your draft and says "Changed by <name> while you were editing". Saving then gets the normal 409 with "Keep mine" or "Use theirs".
- **Large folders (D61).**
  - The table is virtual (@tanstack/vue-virtual) and reads 200-row windows by offset with a `total`, up to offset 100,000 (D20 amended).
  - `order: "number"` uses a new index on `(workspace_id, folder_id, seq_id DESC)`.
  - A window response is checked against the contract 50 rows at a time, yielding between slices, and is dropped if the folder or the rows changed meanwhile.
  - Two extra rows are drawn beyond the visible ones (DESIGN.md, down from 8). On a very fast flick a blank strip can show for a frame.
- **Cause and evidence (D63).** Every item write can carry a cause: a note, evidence URLs and the change it follows from. The item page shows the history, with each change's cause. Writing a cause from the UI is #217, not yet scheduled.
- **Unique ID prefixes (D56).** Creating a hub with a prefix already used in the workspace is 409 `prefix_taken`.
- **Role table (#138).** Workspace settings shows what each role can do, generated from `can()`, so it can't drift from `docs/ROLES.md`.
- **Seed.** `pnpm seed:large` builds a `large` workspace with one folder of 50,000 items in about 10 seconds.

## How to run it

```sh
pnpm install
docker compose up -d db
pnpm seed           # demo workspaces
pnpm seed:large     # the 50,000-item folder
pnpm dev            # http://localhost:5173 — sign in as owner@example.com / 16bit-dev-password
```

To see live sync, open the same folder in two browser profiles, signed in as two people, and edit in one. Docker only: `docker compose up -d --build`, then `docker compose run --rm migrate node src/seed.ts --force`, and sign in on http://localhost:8080.

## What the team would change about the workflow

- **Measure performance the way users run the app.** The scroll budget passed and failed at random on the Vite dev server: 26 long tasks in one run, none in the next. Vue's development build is much slower than what users get. Measuring the production build made five runs in a row clean. Performance budgets should be measured on a production build from the start.
- **Stacked PRs and squash merges don't mix well.** #227 was built on #195's branch. After #195 was squash-merged, GitHub didn't retarget #227, and the merge base was wrong, so the diff showed 30 files and three spurious conflicts. Next time either merge the base PR with a merge commit, or retarget and merge `main` into the stacked PR straight away.
- **Agents can stall silently.** The frontend agent stopped for about 5.5 hours with no report while GitHub was timing out, and you noticed before I did. Now any agent waiting on CI or the network is told to retry a few times and then report what it has. I'll also check the PR's activity myself when a long-running agent goes quiet.
- **Reviewers kept finding concurrency bugs, this time in the protocol.** They found:
  - feed messages that could skip changes, fixed with `hubIds` and a restart pin;
  - unbounded socket queues and half-open sockets;
  - window bookkeeping that could open the wrong item;
  - a history paging race;
  - a stale window applied after its slices were interrupted.

  The M1 habit held: each one became a test that forces the interleaving and fails without the fix.
- **New scope arrived mid-milestone and stayed contained.** The agent coordination brief went in as one decisions PR. Only item 1 (cause and evidence) entered M3, and everything else was filed as issues for later milestones with its open details flagged. The milestone grew by two issues, not twelve.
